## 3. รูปแบบโจทย์ทดสอบ

แต่ละรายการมี `id`, `topic`, `operation`, `args`, `expected`, `check`, `domain`, `kind`, `contract`, `priority` และ `tolerance`

- `normal`: กรณีใช้งานทั่วไป
- `boundary`: กรณีที่ผลลัพธ์ธรรมดาอาจทำให้สรุปทางคณิตศาสตร์ผิด
- `invalid`: ข้อมูลว่าง รูปแบบผิด หรือพารามิเตอร์ไม่ถูกต้อง
- `mathematical`: เกณฑ์ค่าคณิตศาสตร์ การวินิจฉัย หรือการแสดงสมการที่ต้องถูกต้อง
- `proposed-validation`: ข้อเสนอ validation ที่ยังต้องตกลงก่อนถือเป็นข้อกำหนดของผลิตภัณฑ์

`priority` เป็นข้อเสนอเบื้องต้น ไม่ใช่การอนุมัติ release gate ของผู้ใช้

### วิธีเปรียบเทียบคำตอบ

ปฏิยานุพันธ์ไม่เทียบข้อความหรือค่าคงที่โดยตรง แต่ตรวจว่าอนุพันธ์ของผลต่างระหว่างคำตอบจริงกับคำตอบอ้างอิงเป็นศูนย์บนช่วงโดเมนที่ระบุ ไม่ใช่การยืนยันว่า complex branch เท่ากันทั่วทั้งโดเมน ส่วนค่าตัวเลขใช้ absolute และ relative tolerance เท่ากับ $10^{-9}$

โจทย์ $1/x$ ต้องอธิบายคำตอบจริงเป็น $\ln|x|+C$ บนแต่ละช่วงของโดเมน การทดสอบเชิงสัญลักษณ์ด้วย `log(x)` เพียงอย่างเดียวไม่รับรองความถูกต้องของคำอธิบายโดเมนใน UI

ลิมิตที่ไม่มีอยู่และปริพันธ์ลู่ออกต้องมีคำวินิจฉัยชัดเจน การคืน `ok=True` พร้อม `None` หรือสัญลักษณ์อนันต์อย่างเดียวไม่ผ่านเกณฑ์นี้ ค่าพื้นที่ในชุดโจทย์หมายถึงพื้นที่เรขาคณิต ไม่ใช่ปริพันธ์ผลต่างแบบมีเครื่องหมาย หากแอปตั้งใจให้ผู้ใช้ระบุฟังก์ชันบนและล่างเอง ต้องตรวจเงื่อนไขและแจ้งเมื่อเงื่อนไขไม่เป็นจริงแทนการสรุปพื้นที่ติดลบ

ผลบวกรีมันน์อ้างอิงคำนวณด้วยจำนวนตรรกยะและจุดตัวอย่างตรงตามวิธี ไม่ใช้ค่าปริพันธ์จริงแทนผลบวกจำกัด

ชุดข้อมูลเป็น trusted local fixture เท่านั้น ตัว runner ใช้ SymPy อ่านนิพจน์ ห้ามนำ JSON จากผู้ใช้ภายนอกหรือ payload อันตรายมารันโดยไม่ทำ sandbox เพิ่ม

## 5. วิธีรันซ้ำ

รันจากโฟลเดอร์โครงการ:

```bash
.venv/bin/python -m pytest tests/ -q
.venv/bin/python docs/testing/build-test-dataset.py
.venv/bin/python docs/testing/run-test-dataset.py
.venv/bin/python docs/testing/check-content-and-quiz.py
```

runner คืน exit code `1` เมื่อมีกรณีไม่ผ่าน และเขียนรายงานครบก่อนออก การรันใหม่จะเขียนทับไฟล์ชุดข้อมูลที่สร้างและรายงานใน `docs/testing/` จึงควรสำรองรายงานเดิมก่อนเปรียบเทียบหลังแก้บั๊ก ตัว runner วัดเวลาต่อโจทย์แต่ไม่มี hard timeout ต่อกรณี เหมาะกับ fixture ที่กำหนดนี้ ไม่ใช่ stress test ของนิพจน์ไม่จำกัด

## 6. ลำดับทดสอบที่แนะนำ

1. รันชุดเดิมเพื่อยืนยัน baseline แล้วรันชุดข้อมูลใหม่ เก็บรายงานพร้อม commit และวันที่
2. แก้ข้อผิดพลาดด้านค่าคณิตศาสตร์และสมการก่อน พร้อมเพิ่ม regression tests ใน `tests/`
3. ทดสอบบนหน้าจอด้วย `manual-test-cases.csv` ตรวจกราฟ คำใบ้ การ rerun และคะแนนข้ามหน้า โดยไม่ถือว่าผ่านเพราะ helper ผ่าน
4. ตรวจเนื้อหาที่โหลดทุกบท การแสดง LaTeX และคัดตรวจคณิตศาสตร์ของบทเรียนเพิ่มเติมแยกต่างหาก
5. ทดสอบประสิทธิภาพและการเข้าถึงตามแผน เกณฑ์เวลาเป็นเป้าหมายเสนอ ต้องยืนยันกับสภาพเครื่องและผู้ใช้จริง
6. อนุมัติข้อเสนอ validation และขอบเขตฟังก์ชันที่ยังไม่รองรับก่อนกำหนด release gate

ได้ทดลองผ่าน browser-box เพิ่มเติมแล้ว ดู `browser-test-report.md` และ `browser-evidence.json` สำหรับกรณีที่รันจริงและแผนแก้ไข ยังไม่ได้ทำ usability study, load test, security test หรือส่งแบบสอบถามไปยังบริการภายนอก
