# คำสั่งงาน: ตรวจแก้ต้นแบบรายงานโครงงานแคลคูลัส

**สถานะ: เอกสารต้นแบบเพื่อให้นิสิตตรวจสอบและพัฒนาต่อ ไม่ใช่เล่มพร้อมส่งสอบ**

เอกสารในชุดนี้ประกอบด้วยบทที่ 1–5 บรรณานุกรม และภาคผนวก ก–จ ให้ใช้ดูโครงเรื่อง ตัวอย่างการอธิบาย ตาราง และภาพประกอบ ไม่จำเป็นต้องใช้ทุกส่วนหรือคงถ้อยคำเดิม นิสิตต้องเลือกเนื้อหาที่สัมพันธ์กับงานที่ทำจริง เขียนด้วยความเข้าใจของตนเอง และปรึกษาอาจารย์เมื่อพบข้อความที่อธิบายไม่ได้

## เริ่มต้นอย่างไร

1. อ่าน PDF เพื่อเห็นภาพรวม แล้วทำสำเนา Word เป็นฉบับทำงานของทีม เก็บต้นแบบไว้เปรียบเทียบ
2. อ่านคำสั่งงานฉบับนี้ก่อนแบ่งหน้าที่ ร่วมกันเลือกผู้รับผิดชอบและผู้ตรวจทานแต่ละส่วน ไม่ถือว่าบทบาทที่ปรากฏในร่างเก่าเป็นหลักฐานว่านิสิตทำงานนั้นแล้ว
3. ทำรายการข้อสงสัยและส่วนที่ต้องแก้ก่อนเริ่มรวมเล่ม ไม่ต้องแก้โค้ดหรือเพิ่มความสามารถใหม่เพียงเพื่อให้ตรงกับคำกล่าวอ้างในร่าง

## จุดที่ต้องระวังเป็นพิเศษ

- ผลความพึงพอใจและ SUS ในบทที่ 4 เป็นตัวเลขจำลองประกอบการจัดวางเอกสาร ไม่ใช่ข้อมูลผู้เข้าร่วมจริง ห้ามนำไปสรุปผลในบทที่ 5 บทคัดย่อ หรือสไลด์
- รายการอ้างอิงยังไม่ผ่านการตรวจต้นฉบับครบทุกชิ้น ชื่อผู้แต่ง ปี ชื่อเรื่อง DOI เลขหน้า และข้อความสรุปผลต้องตรวจจากบทความหรือสำนักพิมพ์จริง ไม่ถือว่าการมีลิงก์หรือชื่อวารสารพิสูจน์ข้อความทั้งหมดแล้ว
- จำนวนการทดสอบและการแบ่งสถานะในร่างเป็นข้อมูลที่ต้องตรวจย้อนกลับ การทดสอบผ่านไม่ได้พิสูจน์ว่าโปรแกรมถูกต้องทุกอินพุต และการไม่เกิดข้อผิดพลาดไม่ได้แปลว่าจัดการโจทย์ได้ถูกต้อง
- ภาคผนวก จ เป็นแบบกรอกข้อมูล ไม่ใช่ประวัติที่รับรองแล้ว ไม่คัดลอกข้อมูลการศึกษา หน้าที่ ผลงาน หรือช่องทางติดต่อจากร่างเก่าโดยไม่มีหลักฐาน
- ชื่ออาจารย์ที่ปรึกษาให้ใช้รูปสะกด **กิตติพงศ์ ทรัพย์วัฒนาชัย** และตรวจรายละเอียดสังกัดจากข้อมูลที่อาจารย์ยืนยัน
- ข้อกำหนดรูปเล่ม ขนาดตัวอย่าง และเกณฑ์แปลคะแนนต้องตรวจจากคู่มือหรือแผนที่อาจารย์รับรอง ไม่ถือว่าตัวเลขหรือรูปแบบในต้นแบบเป็นข้อบังคับของคณะ

## รายการตรวจแยกตามส่วน

| ส่วน | ไฟล์ต้นแบบ | งานที่ต้องทำก่อนใช้ในเล่ม |
|:---|:---|:---|
| บทที่ 1 | `chapter-01-introduction` | ตรวจปัญหา วัตถุประสงค์ ขอบเขต และประโยชน์ให้ตรงกับงานจริง ปรับตารางเปรียบเทียบเครื่องมือโดยมีหลักฐานและไม่เหมารวมว่าทุกเครื่องมือทำไม่ได้ |
| บทที่ 2 | `chapter-02-background` | ตรวจสูตร เงื่อนไขและตัวอย่าง อ่านต้นฉบับงานวิจัย แยกทฤษฎี ตำรา และงานวิจัยเชิงประจักษ์ ไม่อ้างผลดีต่อการเรียนหากหลักฐานไม่รองรับ |
| บทที่ 3 | `chapter-03-methodology` | ไล่ตัวอย่างหนึ่งโจทย์จากข้อมูลเข้าไปถึงผลลัพธ์ ตรวจแผนภาพและขั้นตอนกับโค้ดจริง ตัดคำอธิบายความสามารถที่ไม่ได้ทำ |
| บทที่ 4 | `chapter-04-results` | ทดสอบหน้าจอจริง ตรวจว่าภาพตรงกับข้อความ รันและเก็บผลทดสอบ เก็บข้อมูลประเมินจริงตามแผน แล้วแทนที่ตัวเลขจำลองพร้อมเขียนผลใหม่ |
| บทที่ 5 | `chapter-05-conclusion` | สรุปเฉพาะสิ่งที่มีหลักฐานในบทที่ 4 ตอบวัตถุประสงค์ทีละข้อ แยกข้อจำกัดที่พบจริงกับสิ่งที่คาดว่าอาจเกิด |
| บรรณานุกรม | `references-bibliography` | ตรวจต้นฉบับทุกแหล่ง ตรวจอ้างในเนื้อหากับท้ายเล่มให้ตรงกัน ตัดรายการที่พิสูจน์ไม่ได้และปรับรูปแบบตามคู่มือ |
| ภาคผนวก ก | `appendix-a-survey` | เทียบข้อคำถามกับ Google Forms จริง ตรวจสูตร SUS และแหล่งเกณฑ์แปลคะแนน ตรวจความยินยอมและความเป็นส่วนตัวก่อนเก็บข้อมูล |
| ภาคผนวก ข | `appendix-b-quiz-bank` | เทียบโจทย์ ตัวเลือก คำตอบ และคำใบ้กับข้อมูลในระบบ แยกคำอธิบายที่เสริมในรายงานออกจากข้อความที่แอปแสดงจริง |
| ภาคผนวก ค | `appendix-c-boundary-matrix` | ตรวจจำนวนและรหัสกรณีจากข้อมูลจริง เทียบผลที่คาดหวังกับผลที่เกิดจริง แยกการปฏิเสธโจทย์อย่างถูกต้อง ข้อจำกัด บั๊ก และกรณีที่ยังตรวจไม่ได้ ไม่เรียกรวมว่าปลอดภัยทั้งหมด |
| ภาคผนวก ง | `appendix-d-installation-guide` | ทดลองติดตั้งและรันตามคำสั่งในเครื่องของตนเอง บันทึกเวอร์ชันและปัญหาจริง ตรวจลิงก์แอปและ QR Code |
| ภาคผนวก จ | `appendix-e-biography` | กรอกประวัติและหน้าที่ตามจริง ตรวจความจำเป็นตามคู่มือ เก็บข้อมูลส่วนตัวนอกฉบับสาธารณะ |

## ตารางบันทึกผลตรวจที่ต้องส่งกลับ

บันทึกข้อพบอย่างน้อยหนึ่งแถวต่อประเด็น ไม่บังคับให้ทุกหัวข้อต้องมีปัญหา และอย่าสรุปว่าตรวจแล้วหากยังไม่ได้เปิดแหล่งต้นทาง

| ส่วน/หน้า/หัวข้อ | ข้อความหรือปัญหาที่พบ | หลักฐานที่ตรวจ | สิ่งที่จะปรับ | ผู้รับผิดชอบ | ผู้ตรวจทาน | สถานะ |
|:---|:---|:---|:---|:---|:---|:---|
| [กรอก] | [กรอก] | [ไฟล์ ผลรัน หรือแหล่งอ้างอิง] | [กรอก] | [ตกลงในทีม] | [อีกคน] | รอตรวจ/กำลังแก้/ตรวจแล้ว |

สถานะของข้อความสำคัญให้เลือกจาก: **ยืนยันแล้ว / ต้องแก้ / รอข้อมูลจริง / ยังตรวจไม่ได้ / ไม่ใช้ในเล่ม**

## คำถามซักซ้อมเพื่อดูความเข้าใจ

1. ลองทำโจทย์เดียวกันในแอปและเครื่องมือเปรียบเทียบ แล้วอธิบายสิ่งที่ต่างกันจากผลจริง ไม่ใช้คำตอบสำเร็จรูปว่าคู่แข่งไม่มีระบบสอน
2. เลือกตัวอย่างอินทิเกรตทีละส่วน อธิบายเหตุผลการเลือกตัวแปร และยกกรณีที่ต้องพิจารณาเกินแนวทาง LIATE ซึ่งไม่ใช่ทฤษฎีบทที่รับประกันทุกโจทย์
3. แสดงข้อมูลผลลัพธ์จริงหนึ่งรายการจากตัวคำนวณ แล้วเทียบกับคำอธิบายโครงสร้างในบทที่ 3
4. เลือกกรณีทดสอบที่คำนวณสำเร็จ ที่ปฏิเสธได้เหมาะสม และที่ยังมีข้อจำกัด อย่างละหนึ่งกรณี อธิบายด้วยเหตุผลทางคณิตศาสตร์
5. อธิบายความแตกต่างระหว่างความสะดวกในการใช้งาน ความพึงพอใจ และผลสัมฤทธิ์การเรียนรู้ คะแนน SUS ไม่ใช่หลักฐานว่าผู้เรียนเก่งขึ้น

## ทดลองระบบและเก็บหลักฐาน

ทำในสำเนาโครงงานของตนเองและสร้างสภาพแวดล้อมแยกก่อนติดตั้งแพ็กเกจ ตัวอย่างต่อไปนี้สำหรับ Linux/macOS หากใช้ Windows ให้ใช้คำสั่งเปิดสภาพแวดล้อมที่ตรงกับระบบ

```bash
git clone https://github.com/SubwatG/calculus-integration-app.git
cd calculus-integration-app
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest tests/ -v
python -m streamlit run app.py
```

เก็บ commit ที่ใช้ เวอร์ชัน Python วันเวลาทดสอบ คำสั่ง ผลผ่าน/ไม่ผ่าน และปัญหาที่พบ ใช้จำนวนทดสอบจากการรันจริงในเวอร์ชันนั้น ไม่กำหนดว่าต้องมีจำนวนเท่าร่างเสมอ
