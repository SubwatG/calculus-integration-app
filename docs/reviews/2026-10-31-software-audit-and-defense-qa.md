# รายงานตรวจสถาปัตยกรรมซอฟต์แวร์และชุดคำถามซ้อมป้องกัน

โครงงาน การพัฒนาเว็บแอปพลิเคชันช่วยเรียนคณิตศาสตร์สำหรับแคลคูลัสเบื้องต้น
ผู้จัดทำ นางสาวขวัญเรือน สำเนียงดี (6621602928), นางสาวเบญจกัฬยาณี พิทยากูล (6621602979)
อาจารย์ที่ปรึกษา อ.กิตติพงศ์ ทรัพย์วัฒนาชัย
ภาควิชาวิทยาการคำนวณและเทคโนโลยีดิจิทัล คณะศิลปศาสตร์และวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ กำแพงแสน

## 4. ความปลอดภัยและการกรองข้อมูลนำเข้า

### 4.1 ช่องโหว่หลัก (ยืนยันด้วยการรันจริง)

เส้นทางข้อมูลคือ `st.text_input` แล้วส่งเข้า `parse_expr` ที่ `utils/sympy_solver.py:68`

```python
return parse_expr(clean_str, transformations=TRANSFORMATIONS, local_dict=LOCAL_MATH_DICT)
```

`parse_expr` ของ SymPy 1.14.0 แปลงสตริงเป็นซอร์สโค้ด Python แล้วเรียก `eval(code, global_dict, local_dict)` (ดู `sympy/parsing/sympy_parser.py:905` ใน `.venv`) โดย `global_dict` ถูกเติมด้วย `from sympy import *` ซึ่งพา `__builtins__` เข้ามาด้วย การใส่ `local_dict` เป็นเพียงการเพิ่มสัญลักษณ์ ไม่ได้ตัดสิทธิ์อะไรออก

ผลการทดสอบบน `.venv` ของโครงงาน (SymPy 1.14.0)

| อินพุต | ผล |
|---|---|
| `__import__('os').getcwd()` | คืนค่าไดเรกทอรีของแอป |
| `open('/etc/hostname').read()` | อ่านไฟล์ระบบได้ |
| `exec('y=1')` | รันได้ |
| `print('SIDE EFFECT')` | พิมพ์ข้อความออกจริง |
| `Symbol('x').__class__.__mro__[1].__subclasses__()` | แจกแจงคลาสทั้งหมดในโปรเซสได้ |

แอปนี้เผยแพร่สาธารณะที่ `https://calculus-integration-app-dwdsz8vq2omsddezfjvday.streamlit.app/` (ตรวจแล้วได้ HTTP 303 ไปยัง `share.streamlit.io/-/auth/app` แปลว่าแอปออนไลน์จริง) ดังนั้นช่องนี้ไม่ใช่ความเสี่ยงเชิงทฤษฎี

ปัจจัยที่จำกัดความเสียหาย ซึ่งต้องพูดให้กรรมการเห็นว่าเข้าใจขอบเขต

- ไม่มี `st.secrets`, ไม่มี `os.environ` และไม่มีตัวแปรสภาพแวดล้อมที่อ่านในโค้ดแอป (ตรวจทั้งรีโปแล้วไม่พบ)
- ไม่มีฐานข้อมูล ไม่มีระบบสมาชิก ไม่มีข้อมูลส่วนบุคคลของผู้ใช้
- สถานะทั้งหมดอยู่ใน `st.session_state` ซึ่งผูกกับเซสชันและหายเมื่อปิดหน้า

แปลว่าผู้โจมตีได้ execution ภายในคอนเทนเนอร์ของผู้ให้บริการ แต่ไม่ได้ credential หรือข้อมูลนิสิตติดไปด้วย ความรุนแรงจึงอยู่ที่ การยึดคอนเทนเนอร์ และการโจมตีต่อไปยังเครือข่ายภายในของผู้ให้บริการ

### 4.2 แนวทางแก้ที่ต้องทำก่อนป้องกัน

ชั้นที่ 1 กรองก่อนถึง parser ด้วย allowlist ที่ระดับอักขระและชื่อฟังก์ชัน

```python
ALLOWED_NAMES = {"x","t","y","u","z","s","r","v","w","pi","e","E","ln","log",
                 "sin","cos","tan","exp","sqrt","abs","inf","oo","theta"}
```

ปฏิเสธถ้ามีอักขระนอกชุด `[0-9A-Za-z+\-*/^().,_ ]` หรือชื่อที่ไม่อยู่ใน allowlist หรือยาวเกิน 200 ตัวอักษร

ชั้นที่ 2 ตัดสิทธิ์ `__builtins__` ตอน parse

```python
SAFE_GLOBALS = {"__builtins__": {}, "Symbol": sp.Symbol, "Integer": sp.Integer,
                "Float": sp.Float, "Rational": sp.Rational}
expr = parse_expr(s, transformations=TRANS, local_dict=LOCAL_MATH_DICT,
                  global_dict=SAFE_GLOBALS)
```

ชั้นที่ 3 จำกัดเวลาคำนวณ เนื่องจาก SymPy ไม่มี timeout ภายใน ต้องรันในโปรเซสลูก

```python
from concurrent.futures import ProcessPoolExecutor
with ProcessPoolExecutor(max_workers=1) as ex:
    fut = ex.submit(sp.integrate, expr, var)
    result = fut.result(timeout=5)   # TimeoutError -> แจ้งผู้ใช้อย่างสุภาพ
```

ชั้นที่ 4 อย่าสะท้อนข้อความ exception ดิบขึ้นหน้าจอ เพราะข้อความของ `parse_expr` มีโค้ดที่แปลงแล้วทั้งก้อนฝังอยู่

### 4.3 การปฏิเสธบริการ (DoS)

- ไม่มีเพดานความยาว อินพุต ตรวจพบเพียงกรณีว่างที่ `sympy_solver.py:66-68`
- อินพุต 50,001 พจน์ ทำให้เกิด `RecursionError: maximum recursion depth exceeded during compilation` และข้อความ `Error from parse_expr with transformed code: ...` มีอินพุตทั้งก้อน (701,305 ตัวอักษรในการทดสอบ) ฝังอยู่ เมื่อหน้าเว็บเอาไปแสดงผ่าน `st.error(res["error"])` (`pages/solver.py:230`) เบราว์เซอร์ต้องเรนเดอร์ข้อความขนาดนั้น ซึ่งทำให้หน้าค้างจนกว่าผู้ใช้จะปิดแท็บ
- `sin(x^x)*exp(x^7)/(1+x^12)` ยังคำนวณไม่จบเมื่อตัดที่ 15 วินาที และไม่มีกลไกยกเลิก เพราะไม่มีทั้งเพดานเวลาและการเช็กจุดตัดกลางคัน

### 4.4 ความเสี่ยงระดับต่ำที่ควรพูดได้

`utils/content_loader.py:106` สร้างพาธจาก `LESSON_DIR / filename` ถ้า `filename` มาจากผู้ใช้จะเกิด path traversal ได้ แต่ในทางปฏิบัติค่ามาจาก `list_lessons()` ที่สแกนไฟล์เอง (`:47-98`) จึงยังไม่ใช่ช่องโหว่จริง ควรตอบตรง ๆ ว่า ยังไม่มีอินพุตผู้ใช้ในเส้นทางนี้ และจะเติมการตรวจ `Path.resolve().is_relative_to(LESSON_DIR)` หากเปิดให้ผู้ใช้เลือกไฟล์เองในอนาคต

## 5. การจัดการสถานะและประสิทธิภาพ

### 5.1 สถานะ

`app.py:11-17` ประกาศคีย์เพียง 3 ตัว คือ `quiz_scores`, `quiz_answers`, `quiz_submitted` แต่หน้าอื่นประกาศคีย์ของตัวเอง เช่น `pages/solver.py:11-18` (`solver_op`, `solver_expr`, `limit_point`) และ `pages/quiz.py:157-174` (9 คีย์) ผลที่ตามมา

- ไม่มี `KeyError` เพราะทุกหน้า initialise เอง แต่สัญญาการใช้สถานะเป็นแบบโดยปริยาย ตรวจสอบยาก
- `quiz_answers` และ `quiz_submitted` ถูกเขียน (`pages/quiz.py:310-311`, `:476-479`) แต่ไม่ถูกอ่านที่ใดเลย เป็นสถานะตาย
- `reset_quiz` (`pages/quiz.py:185-193`) เคลียร์ 8 คีย์ แต่ไม่เคลียร์ `quiz_scores`, `quiz_answers`, `quiz_submitted`, `quiz_questions` ทำให้ข้อมูลข้ามรอบค้างอยู่

## 8. คำถามกรรมการและแนวคำตอบ

### คำถามข้อ 1 (ความปลอดภัยของอินพุต)

กรรมการถามว่า คุณรับนิพจน์คณิตศาสตร์จากผู้ใช้แล้วส่งเข้า SymPy อย่างไร ถ้าผมพิมพ์ `__import__('os').system('id')` ลงในช่องฟังก์ชัน ระบบคุณจะทำอะไร

แนวคำตอบที่ควรพูด

> ระบบใช้ `sympy.parsing.sympy_parser.parse_expr` ที่ `utils/sympy_solver.py:68` ซึ่งภายในแปลงสตริงเป็นซอร์สโค้ด Python แล้วเรียก `eval` ครับ เราทดสอบแล้วว่าอินพุตแบบ `__import__('os').getcwd()` และ `open('/etc/hostname').read()` ทำงานได้จริง แปลว่านี่เป็นช่องโหว่ระดับรันโค้ดได้ ไม่ใช่แค่การกรองสตริงไม่ดี สาเหตุคือ `local_dict` ที่เราส่งเข้าไปเพิ่มสัญลักษณ์อย่างเดียว ไม่ได้ตัดสิทธิ์ `__builtins__` ที่ติดมากับ `from sympy import *` ใน `global_dict` ครับ
>
> ผลกระทบจริงจำกัดอยู่ที่คอนเทนเนอร์ เนื่องจากแอปไม่มี `st.secrets` ไม่มีตัวแปรสภาพแวดล้อม ไม่มีฐานข้อมูล และไม่มีข้อมูลส่วนบุคคล สถานะทั้งหมดอยู่ใน `st.session_state` ที่ผูกกับเซสชัน แต่เนื่องจากเราเผยแพร่บน Streamlit Community Cloud แบบสาธารณะ เราจึงจัดลำดับให้เรื่องนี้เป็นงานแก้ลำดับแรกก่อนการป้องกัน

> แนวทางแก้ที่ออกแบบไว้มี 3 ชั้นครับ ชั้นแรก allowlist ที่ระดับอักขระและชื่อฟังก์ชัน ยาวไม่เกิน 200 ตัวอักษร ชั้นที่สองส่ง `global_dict={"__builtins__": {}}` เข้าไปใน `parse_expr` ชั้นที่สามรันการอินทิเกรตในโปรเซสลูกด้วย `ProcessPoolExecutor` แล้ว `future.result(timeout=5)` เพราะ SymPy ไม่มี timeout ภายในของตัวเอง

ข้อควรระวังในการตอบ ห้ามพูดว่า ผู้ใช้ทั่วไปไม่รู้จักคำสั่งพวกนี้ เพราะกรรมการจะตัดคะแนนทันที ให้ยอมรับและอธิบายกลไก

### คำถามข้อ 2 (ความทนทานต่ออินพุตผิดปกติ)

กรรมการถามว่า ถ้าผมใส่พจน์ 50,000 พจน์ หรือใส่ `sin(x^x)*exp(x^7)/(1+x^12)` ระบบคุณรับมืออย่างไร มี timeout ตรงไหน และผู้ใช้จะเห็นอะไร

แนวคำตอบที่ควรพูด

> ตอนนี้ยังไม่มีเพดานความยาวครับ โค้ดตรวจเพียงกรณีสตริงว่างที่ `utils/sympy_solver.py:66-68` เราทดลองแล้วว่าพจน์ 50,001 พจน์ทำให้เกิด `RecursionError` และข้อความผิดพลาดของ `parse_expr` มีโค้ดที่แปลงแล้วทั้งก้อนฝังอยู่ ในการทดสอบของเราข้อความยาว 701,305 ตัวอักษร แล้วหน้าเว็บเอาไปแสดงผ่าน `st.error(res["error"])` ที่ `pages/solver.py:230` ทำให้เบราว์เซอร์ค้าง
