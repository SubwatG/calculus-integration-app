## หลักฐานที่ตรวจเอง

- `compute_limit_near('abs(x)/x',0)` คืน 1 ทั้งที่ขั้นตอนแสดงลิมิตซ้ายเป็น -1 และขวาเป็น 1 จึงไม่ควรสรุปลิมิตสองด้านว่ามีค่า (`utils/limit_solver.py:51-59`)
- `compute_area_between('x','0',-1,1)` คืน 0 แต่พื้นที่เรขาคณิตคือ 1; สลับฟังก์ชันบนช่วง [0,1] ได้ -0.5 (`utils/area_solver.py:47-64`)
- `compute_improper('1/x**2',1,2)` คำนวณได้ 1/2 ถูกต้อง แต่สูตรผลลัพธ์แสดงขอบบนเป็น infinity ผิด (`utils/improper_solver.py:54-63`)
- `compute_improper('1/x',-1,1)` ส่ง `ok=True` พร้อม NaN ไม่อธิบายการแยกช่วงและการลู่ออก
- ตัว parser ยอมรับการเรียก Python นอกขอบเขตคณิตศาสตร์: parent ตรวจด้วยการเรียกฟังก์ชัน sqrt ของโมดูล math ผ่านช่อง parse โดยไม่เขียนไฟล์หรือสั่ง shell ได้ผล 2.0 ช่องกรอกจึงไม่ควรถูกเปิดสู่สาธารณะในสถานะนี้
- `tests/test_area_solver.py:14-18` ตรวจเพียงผลไม่เป็น None ไม่ตรวจค่าพื้นที่จริง

ข้อแก้ไขจากรายงานย่อย: อินทิกรัลของ 1/x² จาก 1 ถึง 2 เท่ากับ **1/2 ไม่ใช่ 1/4**; อย่าใช้ค่าคาดหวังผิดจากรายงานย่อยเป็น regression test

## งานที่ต้องทำก่อนส่งให้ผู้อื่นใช้งาน

### 1. ความปลอดภัยของช่องกรอกสมการ

เจ้าของ: อาจารย์

- ระหว่างยังไม่มี parser ที่ตรวจรับแล้ว ให้ใช้เฉพาะโจทย์ตัวอย่างที่ระบบกำหนดไว้ ไม่รับนิพจน์อิสระจากผู้ใช้ภายนอก รวมถึงช่อง preview
- ถ้าคง input อิสระ ต้องใช้ parser ที่ยอมรับเฉพาะไวยากรณ์/ชื่อ/ฟังก์ชันที่อนุญาต ตรวจต้นไม้ไวยากรณ์ และปฏิเสธ attribute access/import/คำสั่ง Python ไม่ใช้ eval กับ input ที่ยังไม่ตรวจ
- ตรวจช่อง parse ทุก solver และ `utils/math_render.py` ไม่แก้เพียงหน้าเครื่องคิดเลข
- จำกัดขนาดและความซับซ้อนของ input; try/except หรือ length cap อย่างเดียวไม่ป้องกัน computation ค้าง และไม่ใช่หลักประกันความปลอดภัย
- การตั้ง `__builtins__={}` พร้อมเปิด namespace ทั้งหมดของ SymPy ไม่ควรถูกถือว่าเป็น sandbox ที่พิสูจน์แล้วจาก payload เพียงหนึ่งหรือสองตัว

เกณฑ์ตรวจรับ: input คณิตศาสตร์ที่ประกาศรองรับผ่าน; Python syntax นอกขอบเขตถูกปฏิเสธ; ไม่มีเส้นทาง preview/solver ที่ข้าม parser; ถ้าทำไม่ทัน ปิด input อิสระและชี้แจงข้อจำกัด

### 2. ความถูกต้องและการตัดฟีเจอร์ที่ยังไม่พร้อม

- ลิมิตสองด้านต้องเทียบซ้ายและขวา ไม่ใช้ค่า default ทางขวาแทนสองด้าน
- พื้นที่ต้องเป็นอินทิกรัลของค่าสัมบูรณ์ของผลต่างหรือแยกช่วงตามจุดตัด ไม่ใช่ abs ของอินทิกรัลทั้งช่วง
- ปริพันธ์ไม่ตรงแบบต้องตรวจขอบเขตและจุดเอกฐาน หากยังแยกช่วงทั่วไปไม่ได้ ให้จำกัดโจทย์ที่รองรับและแสดงข้อความชัดเจน ไม่ตอบ NaN ในฐานะผลสำเร็จ
- ปริมาตรให้ตัดสินใจหนึ่งทาง: รองรับ disk เท่านั้นแล้วถอด washer ออกจากตัวเลือก หรือซ่อนทั้งหน้า/ลิงก์ใน release นี้ ไม่จำเป็นต้องทำ washer ให้ครบภายในวันเดียว
- `pages/lessons.py:26,84-86` อ้าง volume แต่ `app.py:24-65` ไม่ลงทะเบียน เป้าหมาย navigation ไม่สอดคล้อง ต้องแก้และทดสอบกดจากแอปจริงก่อนส่ง

## แบ่งงาน 3 คน

### นักศึกษาคนที่ 1: ความถูกต้องของลิมิตและพื้นที่

งบงานประมาณ 8–10 ชั่วโมง

เจ้าของไฟล์หลังอาจารย์ส่งต่อ parser: `utils/limit_solver.py`, `utils/area_solver.py`, `pages/limit_approach.py`, `pages/area_between.py`, `tests/test_limit_solver.py`, `tests/test_area_solver.py`

1. เขียน test ที่ล้มเหลวจากบั๊กจริงก่อนแก้
2. แก้ลิมิตสองด้านพร้อมข้อความเมื่อไม่มีลิมิต
3. แก้พื้นที่กรณีสลับฟังก์ชันและตัดกันกลางช่วง
4. ตรวจช่วงและโดเมนที่ประกาศรองรับ ไม่พยายามแก้ทุกนิพจน์เชิงสัญลักษณ์
5. ทดสอบหน้าเว็บแล้วอธิบายเหตุผลทางคณิตศาสตร์ให้อาจารย์ฟัง

ตรวจรับ: abs(x)/x ที่ 0 ไม่มีลิมิตสองด้าน; x กับ 0 บน [-1,1] พื้นที่ 1; สลับลำดับฟังก์ชันแล้วพื้นที่เท่าเดิม; จุดเอกฐานต้องไม่ถูกแสดงเป็นพื้นที่ปกติ

### นักศึกษาคนที่ 2: วงจรการเรียนรู้และแบบทดสอบ

งบงานประมาณ 8–10 ชั่วโมง

เจ้าของไฟล์: `pages/riemann.py`, `pages/quiz.py`, `utils/quiz_engine.py`, `data/quizzes/`, `tests/test_quiz_data.py` และไฟล์ทดสอบ quiz ใหม่

1. เพิ่มตารางเทียบ L/R/M กับค่าปริพันธ์จริงและ error สำหรับค่า n ปัจจุบัน
2. เพิ่มตารางหลายค่า n ให้เห็นการลู่เข้า ไม่จำเป็นต้องทำ log-log plot
3. เพิ่มคำถามคาดการณ์ก่อนเลื่อนสไลเดอร์และคำถามสะท้อนผลหลังทดลอง
4. เพิ่ม/ปรับข้อสอบจุดเข้าใจผิดเรื่องลิมิต พื้นที่ และจุดเอกฐาน รวมไม่เกิน 6 ข้อใหม่
5. ทดสอบผิดครั้งแรกได้คำใบ้ ไม่เปิดเฉลยทันที; ตอบซ้ำไม่เพิ่มคะแนนผิด; เริ่มใหม่และเปลี่ยนชุดได้

ตรวจรับ: มีค่าจริงและ error ที่ตรวจเทียบได้; widget เปลี่ยนแล้วผลอัปเดต; ผู้เรียนทำกิจกรรมและ quiz จบได้; นักศึกษาอธิบายตัวลวงได้ทุกข้อ

### อาจารย์: ขอบเขต ความปลอดภัย ความหมายทางคณิตศาสตร์ และรวมงาน

งบงานประมาณ 6–8 ชั่วโมง; หากแก้ parser/โดเมนทั่วไปไม่ทัน ใช้การจำกัด input แทน

เจ้าของไฟล์: parser กลางใหม่, `utils/math_render.py`, `utils/improper_solver.py`, `pages/improper_integrals.py`, `tests/test_improper_solver.py`, `app.py`, `pages/lessons.py`, `pages/substitution.py`, `README.md`, `CONTEXT.md`, `requirements.txt`; งาน survey เดิมให้อาจารย์รักษาเอง

1. ล็อก release scope และ input ที่รองรับ
2. วาง parser contract และย้าย import ก่อนส่ง solver ให้คนที่ 1; จากนั้นไม่แก้ไฟล์ของนักศึกษาพร้อมกัน
3. แก้สูตรขอบเขตและ verdict ปริพันธ์ไม่ตรงแบบ หรือจำกัดเป็นโจทย์ที่ตรวจแล้ว
4. ตัดสิน volume และทำเมนูให้ตรงกัน
5. ตรวจข้อความ u-sub: u=sin(x) ไม่ควรถูกประกาศว่าผิดหลักการในทุกบริบท; ควรอธิบายว่าไม่เหมาะกับโจทย์/ช่วงที่กำหนด
6. ตรวจ LIATE: เป็นแนวทางเลือก ไม่ใช่กฎใช้ได้เสมอ; การเลือกไม่เหมาะไม่เท่ากับหาคำตอบไม่ได้

8. รวมงาน รันทดสอบ และตรวจ mobile กับผู้ใช้จริงก่อนเผยแพร่
