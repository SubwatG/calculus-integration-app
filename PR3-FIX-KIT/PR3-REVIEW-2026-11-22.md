### MATH-01 · ระดับ สูง · สถานะ ยังไม่แก้

**สิ่งที่พบ**
ฟังก์ชัน `compute_area_between("sin(120*pi*x)", "0", 0, 1)` คืนค่าประมาณ `8.377580398548328e-10` และรายงาน `ok=True`

**ค่าที่ถูกต้อง**
พื้นที่คือ

$$A=\int_0^1 |\sin(120\pi x)|\,dx=\frac{2}{\pi}\approx 0.6366197724$$

**สาเหตุ**
ตัวหาจุดตัดที่ `utils/area_solver.py:170` สุ่มเพียง 61 จุด

```python
xs = [a_val + (b_val - a_val) * i / 60.0 for i in range(61)]
```

เมื่อแทนค่าจะได้ $\sin(120\pi \cdot i/60)=\sin(2\pi i)\approx 0$ ทุกจุด ทำให้ไม่เห็นการเปลี่ยนเครื่องหมาย ระบบจึงถือว่าไม่มีจุดตัด แล้วอินทิเกรต $\sin(120\pi x)$ ตรง ๆ ซึ่งได้ศูนย์บวกความคลาดเคลื่อนเชิงตัวเลข

**แนวทางแก้**
เปลี่ยนจากการเรียก `subs` 61 ครั้ง เป็น `sp.lambdify` แล้วประเมินแบบ vector ที่อย่างน้อย 2,001 จุด จากนั้นหา sign change และทำ bisection ด้วยฟังก์ชันตัวเลขเดียวกัน

**เกณฑ์ผ่าน**
- ได้ค่าประมาณ $2/\pi$ ภายใน tolerance $10^{-6}$
- มีเทสต์ Regression สำหรับเคสนี้

```python
piece_area = abs(piece_integral)
```

**แนวทางแก้**
- เพิ่มการสุ่มหนาแน่นภายในช่วง (เช่น 401 จุด ไม่รวมปลาย) แล้วตรวจว่าทุกค่าเป็นจำนวนจริงและจำกัด

- ห้าม `abs()` ค่าที่เป็นเชิงซ้อนหรืออนันต์

**เกณฑ์ผ่าน**

- ข้อความบอกว่า $\sqrt{x}$ ไม่เป็นจำนวนจริงบนช่วงนี้
- มีเทสต์ Regression

**สิ่งที่พบ**

| โจทย์ | ผลที่ระบบคืน | ผลที่ควรเป็น |
|---|---|---|
| $\int \frac{1}{x}\,dx$ | $\ln x + C$ | $\ln\lvert x\rvert + C$ |
| $\int \tan x\,dx$ | $-\ln(\cos x) + C$ | $-\ln\lvert\cos x\rvert + C$ |
| $\int \frac{1}{x\ln x}\,dx$ | $\ln(\ln x) + C$ | $\ln\lvert\ln x\rvert + C$ |

#### MATH-15 · ระดับ กลาง · สถานะ ยังไม่แก้

**สิ่งที่พบ**
`compute_tangent("x**(1/3)", -1)` และ `compute_tangent("x**(2/3)", -1)` คืน `status="undefined_point"` พร้อมข้อความว่า f(x) ไม่นิยามที่ x = -1

**เหตุใดจึงผิด**
$x^{1/3}$ นิยามที่ $x=-1$ และมีค่า $-1$ อนุพันธ์คือ $\frac{1}{3}x^{-2/3}$ ซึ่งที่ $x=-1$ เท่ากับ $\frac{1}{3}$ ดังนั้นเส้นสัมผัสคือ $y=\frac{x}{3}-\frac{2}{3}$

$x^{2/3}$ นิยามที่ $x=-1$ และมีค่า $1$ อนุพันธ์คือ $\frac{2}{3}x^{-1/3}$ ซึ่งที่ $x=-1$ เท่ากับ $-\frac{2}{3}$ ดังนั้นเส้นสัมผัสคือ $y=-\frac{2x}{3}+\frac{1}{3}$

**สาเหตุ**
ตัวแยกนิพจน์ใช้รากที่สามเชิงซ้อน (principal root) ของ SymPy เมื่อแทน $x=-1$ จึงได้จำนวนเชิงซ้อน แล้วระบบตีความว่าไม่อยู่ในโดเมนจำนวนจริง

**แนวทางแก้**
- แปลง $x^{p/q}$ ที่ $q$ เป็นเลขคี่เป็น `sp.real_root(x, q)**p` หรือ `sp.cbrt(x)` ก่อนตรวจโดเมน
- เพิ่มเทสต์ `x**(1/3)` และ `x**(2/3)` ที่ $-1$, $-8$ และ $1$

**เกณฑ์ผ่าน**
- `x**(1/3)` ที่ $-1$ ได้ $m=\frac{1}{3}$ และเส้นสัมผัส $y=\frac{x}{3}-\frac{2}{3}$
- `x**(2/3)` ที่ $-1$ ได้ $m=-\frac{2}{3}$ และเส้นสัมผัส $y=-\frac{2x}{3}+\frac{1}{3}$
- ไม่มีข้อความ "ไม่อยู่ในโดเมนจำนวนจริง" สำหรับจุดนี้

### 10.3 ข้อความอธิบายที่ควรปรับ

#### EXPL-01 · ระดับ กลาง · สถานะ ยังไม่แก้

**สิ่งที่พบ**
`compute_tangent("sqrt(x)", 0)` และ `compute_tangent("x**(1/3)", 0)` สรุปว่าเป็น "จุดมุมหัก (Corner Point)" ทั้งสองกรณี

ข้อความจริงจากระบบ

```text
sqrt(x):  f'_-(0) = - \infty i   f'_+(0) = \infty
          กราฟมีลักษณะเป็นจุดมุมหัก (Corner Point)

x^(1/3):  f'_-(0) = - \infty \sqrt[3]{-1}   f'_+(0) = \infty
          กราฟมีลักษณะเป็นจุดมุมหัก (Corner Point)
```

**เหตุใดจึงผิด**
- $\sqrt{x}$ ไม่นิยามเมื่อ $x<0$ ดังนั้นอนุพันธ์ทางซ้ายไม่อยู่ในโดเมนจำนวนจริง ไม่ใช่ $-\infty i$
- $\sqrt[3]{x}$ นิยามทุกจำนวนจริง และอนุพันธ์สองข้างต่างพุ่งไป $+\infty$ จึงเป็นเส้นสัมผัสแนวดิ่ง ไม่ใช่มุมหัก
- "Corner Point" ควรใช้เมื่ออนุพันธ์สองข้างเป็นจำนวนจริงจำกัดแต่ไม่เท่ากัน เช่น $|x|$ ที่ 0

**แนวทางแก้**
แยกสามกรณีใน `utils/tangent_solver.py:357-372`

1. ทั้งสองข้างเป็นจำนวนจริงจำกัดและไม่เท่ากัน → Corner Point
2. อย่างน้อยหนึ่งข้างเป็นอนันต์ → เส้นสัมผัสแนวดิ่ง หรืออนุพันธ์ไม่จำกัด
3. อย่างน้อยหนึ่งข้างไม่อยู่ในโดเมนจำนวนจริง → ระบุว่าฟังก์ชันไม่นิยามข้างนั้น

**เกณฑ์ผ่าน**
- ไม่มีคำว่า "Corner Point" ในสองเคสนี้
- มีคำว่า "แนวดิ่ง" หรือ "ไม่อยู่ในโดเมนจำนวนจริง" ตามกรณี
